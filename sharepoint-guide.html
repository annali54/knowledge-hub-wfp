1. What SharePoint can and can't do

A modern SharePoint page is a grid of "web parts" — small pre-built modules like a news list, a document library view, a quick-links panel, a Yammer feed. As a site admin with no code, you are limited to the web parts Microsoft ships plus whatever your tenant admin has enabled. That's what your current page uses.

What this means for the prototype you're looking at:

  • The browse view, the filter rail, the collections strip — all buildable natively using a Highlighted Content web part pointed at a document library with custom metadata columns.
  • The smart-search / ask-the-library experience — not buildable natively. SharePoint has keyword search and (on some licenses) Copilot, but you can't natively embed a custom AI-answer panel with citations. This needs either Microsoft's Copilot Studio or custom code.
  • The 1-click upload with AI-drafted tags — partly buildable with Power Automate + AI Builder (a Microsoft no-code flow), but the user experience will be clunkier than the prototype.
  • The insights dashboard — SharePoint's built-in Site Analytics gives you views, unique visitors, and popular pages. For custom dashboards (coverage heat map, queries with no answers), you'll either embed a Power BI report or use the custom code path.
The honest headline: there is no way to reproduce this entire prototype using only the point-and-click SharePoint authoring UI. You'll either accept a reduced version, or bring in one round of developer help to build it properly. Both are fine — it depends on budget and timeline.

3. Path A — Native SharePoint page

You can do this today, alone, with no code. You will recreate the browse/filter/collections experience and a basic upload flow. You will not have smart search or a rich insights dashboard.

Before you start

  • Confirm you have Site Owner (not just Member) permission on the Program Learning Library site. Go to the gear icon → Site permissions → check your row says "Owner".
  • In the site gear → Site information, confirm the site template is Communication site (it is — the page layout you showed me is the comm-site layout). If it's a Team site, most of this still works but the styling differs slightly.

Step-by-step

1
Create a document library called "Resources"

Gear icon → Site contents → + New → Document library. Name it "Resources". This will hold every PDF, deck, video, etc. This is the backbone — every filter, every card, every search result reads from this library.

2
Add the metadata columns

In the new library, click + Add column for each of the following. Using the column types listed matters — they power the filters later.

ColumnTypeNotes
TitleSingle line of textAlready exists; rename if needed
SummaryMultiple lines of text (Plain)Plain — not rich text
Product TypeChoiceValues: Technical Note, Case Study, Blog, Report, Presentation, Tool, Video
GeographyChoice (multi-select)Countries + "Global"
TopicManaged MetadataRequires term store access — see note below
Author(s)Person (multi-select)Pulls from your Microsoft 365 directory
LanguageChoiceEN, ES
Publication DateDateSeparate from the file's upload date
PartnersSingle line
FundersSingle line
CollectionChoiceYour flagship collections
TagsManaged MetadataThe controlled vocabulary
About Managed Metadata. These are controlled vocabularies managed centrally by your tenant admin in the "term store". They're better than plain text because they prevent "district WASH office" vs "District Wash Office" vs "DWO" drift. If you don't have term store access, use Choice columns for now and ask IT to migrate them to Managed Metadata later. Don't block launch on this.
3
Edit the homepage

Navigate to the Program Learning Library homepage. Top right → Edit. The page becomes editable in sections. Remove the existing web parts (hover each one → trash icon), confirming with yourself before each that nothing is lost (see Section 8).

4
Add the hero and collections strip

Click the + between sections → choose a two-column layout. In the left column add a Text web part and paste a hero title + subtitle. In the right, add a Button web part that opens the upload form.

Below, add a new section with a four-column layout and drop a Quick Links web part. Set layout to "Tiles", set each tile to a collection (link to a filtered library view — you'll create those in the next step).

5
Build filtered library views

Go back to the Resources library. Top right → All Documents dropdown → Create new view. Create views called "Scaling with Government", "Learning & Innovation Agenda", etc. — each filtered by Collection = [name]. These become the targets of your tile links.

6
Add the browse list to the homepage

Back on the homepage in edit mode, add a Highlighted Content web part. Point it at the Resources library. Choose List layout. Under Filter and sort, set "Sort by: Most Recent". This is the equivalent of the current "Latest / Featured / Trending" tabs.

For "Featured" and "Trending", create two more Highlighted Content web parts in tabs — Featured filters by Collection = Strategy, Trending sorts by Most viewed.

7
Add the filter rail

In a narrow right-column section, add a Quick Links web part per filter facet (Geography, Topic, Product Type, etc.). Each link inside it goes to a pre-filtered library view. It's not a live faceted filter — it's a curated list of saved filter views. Good enough, and visually close to the current page.

8
Improve the upload flow with Power Automate + AI Builder

This is the closest native equivalent to the 1-click upload in the prototype. It requires a Power Automate license (most M365 Business Premium and E3+ users have it).

  1. In Resources library, top right → Integrate → Power Automate → Create a flow.
  2. Choose the template "When a new file is added, extract information using AI Builder".
  3. In the flow editor, add an AI Builder action: Summarize text (pointed at the file's text content) → write the result back to the Summary column.
  4. Add a second AI Builder action: Categorize text with your topic vocabulary → write to Topic.
  5. Add a third: Detect language → write to Language.
  6. Save. Test it by uploading a PDF and watching the columns auto-populate within a minute.
Reality check. The prototype's upload experience shows AI output inline and lets you review before publishing. Power Automate runs in the background after upload — so you get similar end metadata, but the UX is "drop file, come back in 30 seconds, review the columns it filled". Acceptable for most contributors.
9
Add a basic insights tab

Create a second page called "Insights". Add the Site Analytics web part (top-bar → Analytics on any page — it's usually available). Supplement with two Highlighted Content web parts: "Most viewed this month" (sort: Most popular) and "Recently added" (sort: Most recent).

For the richer dashboard — coverage heat map, contributions leaderboard, queries-with-no-answers — you need Power BI. Build a Power BI report reading from the Resources library, publish it, and embed it on the Insights page using the Power BI web part.

4. Path B — Embed the prototype

If your tenant has the Embed web part enabled and allows the hosting domain, you can drop the prototype into a SharePoint page as a full-width iframe. The prototype reads document metadata from your real SharePoint library via the Microsoft Graph API.

What you need

  • Somewhere to host the HTML — your tenant's SharePoint tenant assets library works, or a company-approved static hosting service (Azure Static Web Apps is the path of least resistance for an M365 tenant).
  • A registered Azure AD app with Sites.Read.All permission on the site — this is a 15-minute job for your tenant admin.
  • Your IT team to allow-list the hosting domain in SharePoint's embed allow-list (Settings → SharePoint admin → Configure HTML field security).

How it works

  1. You keep managing documents and metadata in the Resources library (as in Path A).
  2. The prototype calls Graph to fetch the library on page load and renders the browse view.
  3. Uploads post files back to the library; AI tagging runs client-side via Azure OpenAI (you'll need a subscription, which most M365 tenants can get).
  4. You embed the hosted URL on your SharePoint page using the Embed web part: 
    <iframe src="https://your-hosted-app.azurestaticapps.net" 
        width="100%" height="1400"></iframe>

5. Path C — SPFx web part

SPFx is Microsoft's official framework for custom SharePoint extensions. The prototype is converted into a web part (or set of web parts) and installed into your tenant's app catalog. Users add it to pages like any native web part.

This is the right long-term home, but it requires:

  • A developer comfortable with TypeScript and React.
  • 4–8 weeks of work (prototype conversion, security review, testing).
  • Tenant admin approval to publish to the app catalog.

Budget roughly $15–35k if contracting externally, or one dev for a month internally. The upside is that it runs inside SharePoint's security context — no separate hosting, no allow-listing, single sign-on comes free.

6. Making the AI parts actually work

Three ways to power the "ask the library" and smart-tagging features in production:

Microsoft Copilot for M365Natural-language search over all your SharePoint content. Works out of the box if you have the license. Not citation-style like the prototype, more chat-style.~$30/user/month

7. The metadata structure — do this regardless of path

Whichever path you pick, the Resources library with its metadata columns is the foundation. It survives from path to path — so invest in getting it right first, and the visual layer can change later without rework.

One opinionated suggestion: the current site has filters for Partners and Funders. Keep these as optional columns — they're sparse on most documents and clutter the filter rail. Make Geography, Topic, Product Type, and Language the "hero" filters and relegate the rest to an "Advanced" collapse.

8. Replacing the existing page without losing anything

Before you hit "publish" on the new page:

  1. Export the current page's contents. Open the old page in edit mode, copy each web part's contents into a Word doc. Also screenshot the full page at 100% zoom.
  2. Audit the Upload / Video Tutorial / Style Guide / Checklist / Agenda / Tag Reference / Insights Dashboard links. Note each target URL. In your new IA, every one of these has a home — Upload → the new upload flow, Style Guide + Checklist + Tag Reference → sidebar "Resources" section, Video Tutorial → keep the same external link, etc.
  3. Build the new page as a second page (name it "Program Learning Library v2 (draft)"). Don't touch the live page yet.
  4. Share the draft with 3–5 power users for a week. Collect feedback. Iterate.
  5. When ready, in site settings → Navigation, update the "Program Learning Library" link to point to the new page. Make the new page the site home (Site information → Select new home page).
  6. Leave the old page live at its old URL for 30 days with a banner "This page has moved → [new URL]". Then archive it.
Don't delete the old page until at least 60 days have passed. Internal links, emails, and external partner bookmarks can all point to it, and SharePoint's link redirection is imperfect.

9. A realistic rollout plan

WeekWhat happens
1Build the Resources library and migrate existing documents into it with metadata. This is the longest and least glamorous step; do it first.
2Build Path A (native page) as a draft. Invite 3 power users to test.
3Wire up Power Automate + AI Builder for tagging. Test uploads.
4Soft launch to the full team. Keep the old page live.
5–8Collect usage data. If the org is hungry for the AI features, commission Path B or C.
90 daysArchive the old page. Review insights. Plan a v2.

This guide assumes SharePoint Online (the cloud version, 2020+ "modern" UI). If your tenant is still on SharePoint 2019 on-prem or using classic pages, most of this still works but the screens look different. Ask your IT team what version you're on — it's in Settings → About.

Questions to bring to your tenant admin before you start:

  • "Do we have Power Automate + AI Builder licenses?"
  • "Can I get Site Owner on the Program Learning Library site?"
  • "Is Managed Metadata / the term store open to me, or do I need to request terms through you?"
  • "Do we have M365 Copilot licenses? Is Azure OpenAI available in our tenant?"
